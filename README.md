# mv_from_note

自分が書いた [note](https://note.com/dhythm) の記事を、動画にするプロジェクト。

## 目的

- **動画の作り方を学ぶ**：企画・台本・モーショングラフィックス・音までを、記事 1 本ずつ実際に作りながら身につける練習の場。
- **記事をもっと分かりやすく届ける**：文章だけでは伝わりにくい主張を、映像にすることで分かりやすくする。
- **動画コンテンツとして配信する**：練習で終わらせず、公開できる品質の作品にすることを目指す。

## 表現の方針

記事の主張を、**キネティックタイポグラフィ中心のモーショングラフィックス**で伝える。文字と図形の動きが主役で、画像や動画は理解や演出を助ける要素として組み込む。

- 先に「原稿の根拠 → 伝える主張 → 画面の言葉」を対応づけ、その意味に合わせて動きを設計する。
- 記事を読んでいない視聴者にも論旨が伝わることを合格条件にする。
- 画面に出す引用は原稿の文のままにし、テストで原稿との一致を確かめる。
- 音楽・効果音はコードで合成し、外部音源は使わない。

詳しい制作方針は [AGENTS.md](AGENTS.md) にまとめている（Claude Code などのエージェントも作業開始時にこれを読む）。

## ディレクトリ構成

記事ごとに `YYYYMMDD_記事タイトル/` のディレクトリを作り、企画から映像までをまとめる。

```
YYYYMMDD_記事タイトル/
├── plan.md        # 企画書（何を伝えるか、尺・画角・色・構成）
├── references.md  # 元記事の引用と、画面の言葉との対応
├── script.md      # 画面に出す言葉の台本（ある場合）
├── prompt.md      # 制作に使った指示。ほかの記事にも流用できる形で残す
├── feedback.md    # 制作中のフィードバックと振り返り
├── assets/        # 静止画などの軽い素材（WebP など）
└── video/         # Remotion のプロジェクト（作品によって複数ある）
```

## 制作の流れ

1. 元記事を全文読み、主張の骨組み（問い → 原因 → 転換 → 方法 → 結論など）に分ける。
2. `plan.md`・`references.md`・`script.md` で企画と画面の言葉を固め、レビューを受ける。
3. Remotion で映像を実装し、テストで台本・引用・タイミングを検査する。
4. 書き出した映像を確認し、`feedback.md` に振り返りを残す。

## 技術スタック

- [Remotion](https://www.remotion.dev/)（React + TypeScript）で映像を組み立てる
- [Vitest](https://vitest.dev/) でタイムライン・読了時間・引用の一致をテスト
- ffmpeg で音声の書き出しや最終エンコード
- フォントは `@remotion/google-fonts`（Noto Sans JP／しっぽり明朝）。レンダリング時にネット接続が必要

## 使い方

各作品の映像ディレクトリに入って実行する。コマンドの詳細は各 `video*/README.md` を参照。

```bash
cd 20261004_レビューの本質とは：品質向上のための協働プロセス/video-kinetic
npm ci
npm test         # 台本・引用・タイミングの検査
npm run studio   # プレビュー
npm run render   # 書き出し（ffmpeg が必要）
```

書き出した動画（`*.mp4` など）と `output/` は Git 管理外。リポジトリには企画書・ソース・軽い素材だけを入れる。

## 外部サービスでの動画生成について

Dreamina AI（Seedance 2.5）などクレジットを消費する生成は、制作手段の選択肢の1つとして扱う。**生成の前には必ず、対象カット・内容・回数・想定クレジットを示してレビューと明示的な承認を得る**（テスト生成も含む）。詳細は [AGENTS.md](AGENTS.md) を参照。

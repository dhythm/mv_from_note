# デザイン改稿・第1段階

## 最優先：ユーザーの追加指示

「もっとバシバシ動いて躍動感ある方が良い」「ミュージックビデオくらいの動きがあっても良い」。これは旧企画の「大きな変形は一度」「微小な動き中心」を上書きする明示指示。速く鋭い登場・退場、画面を横断するタイプ、サイズの急変、切り返し、文字の組み替えを使う。読む間に全要素を停止し続ける必要はない。主文を読める安定時間は確保し、周囲の文字・面・罫線が次の構図へ動いてもよい。スローモーション風の長い補間、数秒かけてカードが合流する動きは避ける。登場・退場は概ね4–10フレーム、意味の組み替え12–18フレームを出発点に、実際の映像で調整する。全編を単純に倍速にしない。

現BGM64BPMは細分拍（128BPM相当）で文字・カットを合わせ、間延びを防ぐ。音楽を後で変える可能性は報告に記載。試作では既存BGMを使用。動きの総量と強弱を上げる。情報を細切れにして読めなくしない。前作以上に躍動感を求められているので、前作をそのままコピーせず発展させる。

ユーザーの評価は「デザインダサい。前に Opus に作ってもらった時はもっとかっこよかった」。現在の動画を微調整するのでなく、文字が画面を支配する映像として設計し直す。

## 比較する実作品

必ず ../20261004_レビューの本質とは：品質向上のための協働プロセス/video-kinetic/src/scenes/Opening.tsx と glyph.tsx、design.ts を読む。あの冒頭はユーザーが「この冒頭、めっちゃ良いです！！」と評価した。紙色そのものを嫌っているわけではない。同じ文字がサイズ、軸、配置、書体を変え、文意を変化させる点が重要。暗背景やネオンを足せば良いと判断しない。

## 今回の問題

- 同じ大きさの中央揃え文章のフェードが続き、映像より説明スライドに見える。
- 小さな角丸カードと影が主役を奪い、対立の圧力や転換の意味が弱い。
- 動画Aが小さな縁付き窓に縮まり、大きな余白が活きていない。
- 動画Bと役割ラベルが重なり、言葉と映像の優先順位が不明。
- 「大きな変形は一度だけ」を守りすぎて文字の演出が均質。読む間の静止は守りつつ、登場、退場、意味の切り替えで強い動きを使う。

## 今回実装する範囲

まず Question と Cause1（冒頭30秒）を大胆に再設計し、Pivot（41–57秒）の動画A配置を代表例として再設計する。他の場面は後で展開するため、まだ全編の完成を報告しない。既存 main.mp4 を上書きせず、design-prototype.mp4（冒頭30秒）と design-pivot.mp4（41–57秒）を video/output に出力する。

- 1280×720、30fps、文章内容と現行時間割は維持。記事にない主張を追加しない。
- 文字を一律46pxから解放。重要な短語は100–160px、補助句は32–48px等、実際に収まるバランスを設計する。太い黒・朱・青の少数色。明朝を使うなら既存の利用可能なローカルフォントを確認し、不在なら太さと配置だけで成立させる。
- 長文は意味の塊に分け、段組みや明確な改行で読む順を作る。逐字入力で読む時間を消費しない。対立は文字・罫線・面の圧力として見せ、角丸吹き出しに頼らない。
- 文字が変形・移動して次の意味へつながるモーションを少なくとも冒頭に一箇所作る。全場面をフェードで切り替えない。過剰な震え、飾りの英語や番号、記事と関係ない装飾は不要。
- 動画Aを画面の大きな面として使い、同時に文字が読める構図を設計。過剰な影・縁・丸角を除く。動画Aの紙・手と文字を重ねるならコントラストを確保。
- 対立の意見を後半の実務家／エンジニアへそのまま対応づけない。変形ではいったん意見を消して共通色の空の形にする。
- 原稿の留保、要件と機能の違い、非技術者に責任を押しつけない意図、無音声・効果音なし、BGMを維持。
- useCurrentFrame/interpolate による再現可能な動き。文字のはみ出し、衝突、読み時間をチェック。

代表静止画を video/output/design-stills に6枚程度出力し、報告は design-revision-report.md に記載。feedback.md に今回の不評と原因、試作の改善内容を追記。全編は未修正である旨を明記。git commit はしない。

まずコードと素材を読んで実装・レンダリングまで続け、質問で停止しない。新しい外部生成サービスを使わず、現在の素材と依存関係を使う。

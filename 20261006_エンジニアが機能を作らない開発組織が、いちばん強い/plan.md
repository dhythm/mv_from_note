# エンジニアが機能を作らない開発組織が、いちばん強い

## 最初に分けること

維持するもの
- 表現形式は、撮影なしのキネティックタイポグラフィ／モーショングラフィックス。文字と図形の動きが主役で、画像は補助。
- 記事の主張は「バイブコーディングをめぐる対立は、どちらか一方が正しいのではなく、役割分担で解ける。実務家が機能を作り、エンジニアが土台と品質を守る。大切なものは変わらず、比重が変わる」。
- 理由を落とさない。どちらにも一理ある理由（ケースバイケース）と、エンジニアがゼロではいけない理由（視野が狭すぎることがある、実務家が言えるのは「ほしい」まで）。
- 結論の前置き（大きな組織を率いているわけではない、思考実験で間違っているかもしれない）。

変えてよいもの
- 上映順。記事は事例 → 対立 → 分担 → 役割 → 結び。映像は対立から入り、「これまでは翻訳するしかなかった」を転換の直前へ寄せる。
- 画面の文言、書体、配色、間。最終判断は作業者。

提案側の仮説（原稿にはない、こちらの発明）
- 「AIに任せればいい」が上の層「機能／実務家」に、「メンテナンスできるはずがない」が下の層「土台／エンジニア」になる対応づけ。原稿は二つの声をそれぞれの役割と同一視していない。対立していたものが、同じ構造の上下になる、という見立てとして使う。

## 動きの課題は1つ

時間の目安は references.md 第3節の読了時間（約94秒）に合わせて調整済み。転換の枠には回転と着地の約2秒を含む。

左右から来た2つの意見の文字ブロックが中央でぶつかって震え、90度回って上下2層に積まれる。上が「機能／実務家」、下が「土台／エンジニア」。

- 意味: 横に並ぶと押し合う（どちらが正しいかの争い）。縦に積むと支え合う（役割の違い）。対立を役割分担で解く、をこの変形一回で見せる。
- 変形は一度だけ。転換の拍で起こす。それ以前は震えたまま止まり、以後は積まれたまま動かない。
- 層の言葉の入れ替え（意見から役割へ）は、着地の瞬間のフェードかカットで行う。二つ目の動きにしない。
- それ以外の文字はフェードとカットだけ。役割の列挙を積み木の追加などで動かさない。

## 合格の条件

note を読んでいない人が見終わって、次を自分の言葉で言えること。
- 二つの声が何で、なぜどちらにも一理あるのか（扱うものの重さで変わる）。
- AIで何が変わったのか（実務家も作れるようになった。これまでは翻訳しかなかった）。
- なぜエンジニアはゼロにできないのか（視野、「ほしい」まで）。
- 結論が断定ではなく、書き手の思考実験としての「比重が変わる」であること。

不合格: 「AIで誰でも作れる」「エンジニアは不要」「仲良く協力しよう」だけが残る。前置きを落として断定に見える。文字を外して分かるかどうかは基準にしない。

## 制作の進め方

- 全編の前に、問いから転換まで（0:00–0:53）の短い区間を等速で書き出して見る。変形の手応えと文字の読める速さをここで確かめる。
- 書き出しの完了と、作品として通ったことは分けて報告する。
- 書き出し中に素材を更新しない。

## 素材

- 必須の画像はない。文字ブロックと図形はコードで作る。
- アイコンを使うなら人と盾だけ。単色の線画で、ブロックの色と合わせる。軽い WebP か SVG。
- 静止画の枚数を進捗にしない。基準画をそのまま動かす素材として渡さない。
- 生成動画は使わない。このカットが良くなる場面がないため。

# JIZURA を動きの語彙として参照する

2026-11-21 のユーザー指示で追加した参考情報。**使うことは必須ではない。** 知らない表現は企画書に書けないので、選択肢を広げるために持っておく。

- リポジトリ: <https://github.com/852wa/JIZURA>（MIT ライセンス）
- ブラウザ版: <https://852wa.github.io/JIZURA/>
- 確認した版と範囲: v0.13.0。README と `docs/EXPRESSION_PACKS.md` を読んだ範囲でまとめた。アプリを動かしての見た目の確認はしていない。版が進んでいたら README を読み直す。

## 何であるか

歌詞を入れると、文字PV（リリックモーション）の表現を組み合わせてカットを自動で組み、MP4 に書き出すブラウザアプリ。1カットを次の10分類の部品の組み合わせで表す。部品は 1,715、配色・書体のセットは 27。

| 分類 | このリポジトリの企画書での対応 |
|---|---|
| レイアウト | 字組み・構図（縦横、語の大きさ、余白、重心） |
| 登場／保持／退場 | 文字が入る・読む間・出る動き |
| 装飾 | 文字に添える図形 |
| 文字の加工 | 袋文字・縁取り・マーカーなどの文字の仕上げ |
| 背景 | 色の面・模様 |
| カメラ | 画面全体の動き |
| 画面効果 | 画面全体に掛かる効果 |
| カット間のつなぎ | 次のカットへ勢いを渡す動き |

各分類の部品名の例は [語彙の一覧](references/vocabulary.md)。

## 企画での使い方

1. カット表を書く前に、分類ごとに「このカットは何で動かすか」を決める道具として使う。レイアウト・登場・保持・退場・カメラ・つなぎを別々に決めると、「全カット同じ登場」「読む間が静止」に気づきやすい。
2. 部品名は、動きの狙いを短く言う語として使う（例: 「画面突き抜け」「直角ターン」「読み追いカメラ」「プッシュ」）。企画書には部品名だけでなく、主役の語と、その動きが運ぶ意味を書く（`AGENTS.md`「企画書兼作業指示書に書くこと」）。
3. 見た目を確かめたいときはブラウザ版で、一般的な短い文を入れて試す。「手法」タブで部品を1つずつ ON/OFF でき、カットごとに部品を差し替えられる。入力はブラウザの中だけで処理されると README にあるが、非公開の原稿をそのまま貼らず、確認に必要な短い文にとどめる。

### 参考になる定石（README「統一感」「文字整列」）

- まとまり（パート）ごとにレイアウト・動き・カメラ・装飾をそろえ、くり返す言葉は同じ見せ方で戻す。
- 動きの方向を交互にする（左→右、上→下）。強い動きは、ここぞという行に回す。
- キメの行は1カットで大胆に見せる（大きな文字・ズームなど）。
- 同じ行の次のカットへ、同じ字は移動し、ほかの字は溶けて変わる（モーフ）。
- かなの字間を詰めて塊で読ませる。助詞（は・が・を・に）を小さく、行の頭の字を大きくする。
- 文字は声より約0.2秒先に出す。効果は重ねすぎない（装飾は1つまで、画面効果はカットごとに1つまで）。

## このリポジトリの方針と合わせるときの注意

JIZURA は歌詞を曲に合わせて見せる道具で、こちらは記事の主張を伝える動画。そのまま持ち込まない点がある。

- **文字の形を崩す部品は基本にしない。** ジッター、グリッチ、爆散、1文字ずつ散る登場・退場、拍ごとの脈動は、読みにくい・低品質と評価された型と重なる（`AGENTS.md`「動きの強さ」、20261018 の `feedback.md`）。行・塊・層・カメラで動かす部品（流れる帯、直角ターン、読み追いカメラ、プッシュ、ワイプなど）を優先する。
- **意味のない装飾を足さない。** 照準線・バーコード・飾りの数字・時刻のような HUD 風の装飾は、主役の語と意味に結びつかないなら使わない。飾りの番号は制作管理情報に見えるので特に避ける。
- **ランダムな組み合わせを企画にしない。** おまかせの結果は案出しの材料。採否は「視聴者に伝える一文」と可読性で決める。
- **NANKA DEKIRU の適合確認の代わりにはならない。** あちらは企画書の作成・改稿の前に必須（`AGENTS.md`「エフェクト参考と制作指示」）。JIZURA を見た場合は、同じ演出参考資料に、見た部品と採否の理由を書く。

## 制作側が使う場合

- **仕組みの参考。** すべての動きが、シードとカット内の時刻（登場・退場の進み具合 0〜1、カット開始からの秒）から決まる。`Math.random()` を描画で使わない。Remotion のフレーム再現と同じ考え方なので、動きの式を読んで翻訳しやすい。読む順は `src/05_anim.js`（登場・保持・退場）、`src/06_layouts.js`（レイアウト）、`src/03_text.js`（文字のモデル）、`docs/EXPRESSION_PACKS.md`（部品の書き方）。
- **描画は Canvas2D。** こちらの方針は、文字を DOM／CSS の層で組むこと（`AGENTS.md`「画面全体の動きの実装（three.js）」）。コードを写すのではなく、動きの式とタイミングを DOM の行・塊へ移す。
- **コードを流用するとき**は MIT ライセンスの著作権表示を残す。
- **素材として書き出す使い方**もできる。グリーンバック／ブラックバック／透過PNG（前景・後景を分けた ZIP も可）で、白い文字と演出だけを書き出せる。ただし文字の層が動画になり、はみ出し・重なりの機械検査が効かなくなるので、主張の文言には使わず、背景や転換の素材にとどめる。出力物の権利は作った人に帰属すると README にある。フォントは Google Fonts から読み込まれるので、書体の利用条件は別に確認する。

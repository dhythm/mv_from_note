# 丸頭キャラのBlenderプリビズ

このプロジェクトの企画側が、構図・人の動き・物との位置関係を試すための素材制作に使う。まずリポジトリの `AGENTS.md` を読む。記事本編を人物劇へ置き換えず、制作側への素材不足の丸投げもしない。本編への合成・音・エンドロゴなどは本編の指示に従う。

## 成功版を入口にする

`assets/approved_character.blend` は承認済み中立形状、`assets/approved_walk.blend` は実測歩行・改良ウェイト・関節補正を持つ2.4秒の編集可能な例。初回は作り直さず `scripts/previs.py new` で独立コピーする。原本を開いて上書きしない。詳細と再実行例は [実行手順](references/workflow.md) を読む。

- `python3 scripts/previs.py check` は素材のハッシュ確認だけでGPUを使わない。
- `new --template walk` は短歩行をコピーし、`new --template character` は中立形状をコピーする。
- Blender/ffmpegは既存のものを使い、`--blender` / `BLENDER_BIN`、`--ffmpeg` / `FFMPEG_BIN` またはPATHで指定する。追加インストールやモデルの再ダウンロードはしない。
- 新しい動作が必要な場合だけ `sample` → `retarget` を使う。現行リターゲットはCMU/cgspeedの骨名・30fpsに対応し、任意リグへの汎用変換ではない。
- 形状を再構築する必要があるときだけ `rebuild-character`。既定ではモデルを保存するだけで、レンダリングしない。

## 形状・動作の判断

[形状とリグ](references/model-and-motion.md) に比率、接続、ウェイト、補正シェイプ、支持足処理をまとめている。承認された特徴は、大きな丸頭、短い首、丸い胴・四肢、単色白、つながった1メッシュ。球と棒の継ぎ足しや平板なシルエットへ戻さない。中立形状の頂点ハッシュを保持することと、動作の見た目が良いことは別に検査する。

実測モーションの時間を基礎にし、骨長・頭身・接地・腕の逃げを適合する。人の歩行を自己流の正弦波等へ置き換えて「実測」と呼ばない。膝のポールは現在の向きへ追従させ、旋回中の足をずっと固定しない。大きな頭に手が入る場合は腕の経路や画角を調整する。物を持たせるなら、手の接触・付着の連続性・離す瞬間を別途検証する。

接地はキネマティックな補正で、重心・床反力・動力学的バランスや全身衝突の物理シミュレーションではない。元データ・利用条件・変更範囲は [出典と利用条件](references/sources.md) に記録する。未計測の指や物体の動きを実測扱いしない。

## 検品してから長くする

1. **形**：新規形状や変更形状は、軽量の正面・側面・斜めで頭身・厚み・つながりをユーザーへ示す。同じ承認済み形状を使う場合は承認を繰り返し求めない。
2. **短動作**：まず必要な代表動作を短く確認。960×540程度・Eeveeで十分。深い曲げ、方向転換、頭へ近づく手など、実際に難しい区間を含める。
3. **連続**：全フレームの隣接一覧を目視し、通常速度で動画を実際に再生する。利用可能な独立担当にも視覚レビューを依頼し、検査範囲を区別する。肘膝・股腹の折れ、体積の脈動、床通過・足滑り、接触、見切れ、カメラ急変を確認する。
4. **必要な尺へ**：短動作で残る欠陥を直してから長くし、1080p等へ出力。追加の全編出力は、直す欠陥や未決の判断があるときに限定する。

`inspect` の足裏・画角・頭腕距離は問題箇所を探す道具。数値だけで自然さや全身無干渉を合格にしない。最終解像度由来の全フレームと再生を確認し、実施できなかったものは未検証と書く。ブラウザの表示落ちとファイル欠けを区別する。

## 保存と報告

出力は `output/previs/<固有名>/` など既存git規則で除外される専用フォルダへ。付属原本は小さな再利用資源として保持し、動画・大量フレーム・ログ・バックアップをスキルやgit対象へ混ぜない。ユーザーの既存シーンを触らず、スクリプトは独立 `--background --factory-startup` プロセスで実行する。M5でMetal初期化がsandboxに妨げられた場合は既存権限の範囲で対処し、別のMacへ切り替えない。

MP4、編集可能なblend、必要なら各クリップ・素材・再現コードのZIPを渡す。統合blendは `assemble` のシーンストリップで内部に3Dを持たせ、外部動画だけの編集ファイルにしない。Blenderバージョン、尺/fps/解像度、パス、編集方法、実現済みと未検証を簡潔に報告する。Library保存を頼まれた場合は、その時点の正規Library手順で保存し、確認済みIDだけを返す。このスキル自体はアップロードや公開を行わない。

現行一式の実行確認と未検証は [検証範囲](references/validation.md) を参照する。

# 原稿と画面の対応

元記事：[AI画像で失敗する人は、ゼロから生成させる人](https://note.com/dhythm/n/n018864f250f1)（公開済み）

原稿：`dhythm/private-note` の `Zettelkasten/PermanentNote/20261110_AI画像で失敗する人は、ゼロから生成させる人.md`。本文は同梱しない。以下は原稿確認時の短い抜粋と、企画書の画面文言案の対応。記事の意味と留保、画面文言の根拠を確認するための資料。

## 主張の一文

AIで作った絵が気持ち悪いのはAIのせいだ、と思っている人に、不自然さはゼロからすべてを生成させていることから来ると伝える。AIは手元の70を80〜90へ引き上げる相棒で、最後の判断と責任は人が持つ。それが筆者の結論である。

冒頭の「なんか、気持ち悪い。」は続きを見る事実です。結論は視聴者への問いかけに戻しません。最後の画面は「相棒として。／責任は、人が持つ。」（完成した本編もこのとおり）

## 数字は何の指標か

原稿の 0、70、80、90、100、および「残りの30」は、どこまでをAIに委ねるかの言い方です。品質スコア、アンケート、生成の成功率、店の数ではありません。画面の目盛りも同じ比喩で、測定器には見せません。原稿にない率や件数は足しません。

## 画面にしないこと

| 原稿にあること | 扱い |
|---|---|
| Nano Banana、GPT Image などの製品名 | 品質が上がった、という範囲にまとめる。UI とロゴは描かない |
| Photoshop | 方法（実物を撮り、光や形を足す）だけ。名前と画面は出さない |
| いらすとや | 出さない。主張に要らない |
| ケンタッキーのメニュー画像、投稿の画像、ITmedia の紙面 | 02 は要旨の語だけ。画像も出典の行も出さない |
| 原稿内のフロートのイラスト（`2026-11-10_17-55-39.webp`、`2026-11-10_23-44-36.webp`） | この企画では使わない。02 は同じ立体のグラスで要旨を伝える |
| 香港の風景写真 | 06 は箱の建物。写真も地名のラベルも出さない。地名は声 |
| 実在の人物、客の顔、作り手の肖像 | 出さない。点と「人の手」の語で足りる |
| 家電の製品 | 部屋と青い円。製品名も製品の形も出さない |

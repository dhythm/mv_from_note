# Fable 5.2 への制作依頼

この動画を、構成の確認から実装、通し、文字のはみ出し検査、修正まで、1回の依頼で最後まで仕上げてください。企画書は到達点ではありません。より伝わり、より魅力的になる判断を自分で行い、実装し、動く映像で確かめてください。

対象は、このフォルダの記事「AI画像で失敗する人は、ゼロから生成させる人」です。

## 目的と主張

「メニューの絵が気持ち悪いのは、AIのせいだ」という見方を、ゼロからすべてを生成させていることへ移します。AIは手元の70を80〜90へ引き上げる相棒で、最後の判断と責任は人が持つ。最後は、その筆者の結論で閉じます。

文字を主役にしたキネティックタイポグラフィ×モーショングラフィックスです。動きの核は、0〜100の目盛りです。0から100へ走る線は途中で折れ、70から90へ伸びる線は滑らかに光る。読む間も、行、語の塊、図の層、画面全体が大きく動き、次の場面へ勢いがつながります。カットごとに字組み、大小、余白、重心、奥行き、動きの緩急を変え、主役の語と意味に結びつけてください。

## 最初に読むもの

次を、作業の前に通して読んでください。過去資料の全文読破を着手条件にはしません。今回の判断に必要な箇所を調べてください。

- リポジトリ直下の `AGENTS.md`。共通方針。この依頼が明示的に委ねる構成・演出の変更は、今回のユーザー指示として扱います。`AGENTS.md` 自体は編集しません。
- 各企画フォルダの `feedback.md`。映像に管理番号を入れないこと、文字の形を崩して動きにしないこと、同じモチーフの一部だけ質感を変えないこと、留保を残して結論は本人の肯定で閉じること、絵コンテの静止画を躍動感の合格にしないこと。
- 原稿：`dhythm/private-note` の `Zettelkasten/PermanentNote/20261110_AI画像で失敗する人は、ゼロから生成させる人.md`。本文はこのリポジトリに同梱していません。開けない場合は、その事実を残し、`references.md` にある抜粋の範囲で進めます。原稿にない事実は足しません。
- このフォルダの `plan.html`、`references.md`、`effects-direction.md`、`assets/storyboard/`、`fable-brief.md` を一式で。絵コンテは意図と構図のラフです。完成画との一致を求める見本ではありません。
- `../okady-work-logo.svg`。最後の制作表示。

必要なら `docs/techniques/typography-motion.md` と `docs/techniques/camera-cheatsheet.md` を参照してください。参照先が開けない場合は、その事実を残し、手元の根拠で進められる部分を進めます。

## 一気通貫で任せること

次を、確認の往復に分けず、この1回で最後までやってください。残作業の一覧や「続けますか」で途中終了しません。

1. 手元の資料と実行環境を確認し、改善の狙いを短く示して着手する。
2. 構成を、主張・留保・本人の結論が残る範囲で確認し、直すなら直してから実装する。
3. 品質を左右する代表区間を先に実装する。0から100が折れる区間と、70から90が伸びる区間、そのつなぎ。等速で確認し、問題があればこの段階で直す。
4. 有効だった表現を全編へ展開する。同じ登場の反復、読む間の静止、後半の失速を点検する。
5. 文字のはみ出しと、文字同士・図との意図しない重なりを全編で機械検査する。約0.25秒間隔に加え、速い移動とカットの境を見る。
6. 欠陥があれば直し、同じ検査をもう一度通す。
7. 再生できる全編、再現できる実装、検査結果、確認した範囲と未確認の範囲を渡す。

努力の設定は high 以上にしてください。代表区間の動き、文字と図の重なり、結びの寄りなど、品質が分かれる箇所は xhigh を使ってください。環境が設定値を返せないときは、返った事実を書き、推測で「high だった」と断定しません。

## 作業範囲

このフォルダの制作物は、あなたが所有します。直してよい。既存のファイルに足すだけ、周辺の不具合は報告のみ、では止めないでください。

- 本編のカット数、順序、長さ、場面の統合や分割。2分01.5秒と13カットは参考案で、固定ではありません。
- 画面文言とナレーション案の要約、語順、改行、声と文字の分担。主張、必要な留保、下記の決定は守ります。
- 字組み、文字サイズ、配色、図形の意匠、配置、カメラ、つなぎ、動きの種類と緩急。
- 実装方法。three.js は図の層の推奨です。別の手段を選ぶ場合は、画面全体の動きと検査のしやすさで選んだ理由を短く残してください。
- 検査、独立した場面の実装、レビューの分担。サブエージェントが使える場合は、独立した作業に限り使えます。使わなくても進めます。委任は費用の多くを占めることがあります。最終的な整合は自分で確認してください。

0、70、90、100、2分01.5秒、13カット、左右40px、寄り2秒、各色コードは参考値です。意味の伝達、ロゴのタイミング、文字が安全域に残ることに必要な数値だけを守ります。既存の絵コンテに合わせるために、より良い表現を諦めないでください。

変更した意図は短く記録し、`plan.html` の該当箇所と `references.md` の対応を現行の内容に揃えます。配置や動きの判断が変わる絵コンテだけ更新し、全枚数の描き直しを目的にしません。

文の長さや文の数の硬い制限は置きません。意味が伝わる書き方を優先してください。

他の企画フォルダと `AGENTS.md` は変更しません。

## 未確定事項の扱い

`plan.html` の冒頭に、判断が要る点が A／B で書いてあります。回答がまだ無いものは、A を前提に進めます。B の承認を待って実装を止めません。

- 要判断 1 と 2 は A。フロートのイラストも、生成動画も使わない。線画のモーショングラフィックスで作る。
- 要判断 3 は A。ナレーションの原稿と、声を置く設計まで。音声ファイルは作らない。この依頼は、API で音声を生成する許可ではありません。

回答が後から B になった場合も、画像・動画の新規生成は制作側では行いません。必要な場面と役割を企画側へ返します。

## 素材とファイル

- 採用する写真・動画ファイルはありません。グラスは、出るカットのすべてで同じ線画です。一部のカットだけ別の質感にしないでください。
- 他者のメニュー画像、投稿、記事の紙面、製品の UI、ロゴ、実在の人物は描きません。09 は要旨と「出典：ITmedia、投稿」の一行です。
- エンドロゴは `../okady-work-logo.svg`。背景 `#d2ff1a`。形、書体、色、比率は変えない。絵コンテのはじめの印はラフなので、ロゴの形の見本にしません。
- 実装とプレビューは `video/`、進捗は `video/progress.md`、結果は `production-report.md`。
- 長いツール呼び出しのあいだも、`video/progress.md` に、今どの区間を作っているかを残してください。
- プレビュー動画はローカルに保存できます。生成動画や大きい中間ファイルを Git へ入れないことと、プレビューを作れないことを混同しないでください。
- フォントは利用条件を確認し、再現に必要なら許諾されたものを同梱できます。

## 技術条件

- 16:9、1920×1080、30fps。動きはフレーム時刻から再現できる状態にします。実時間のループや、シークすると変わる計算を、本編の動きにしません。
- 文字は、詰め組、行のマスク、文字単位の外接矩形が取れる DOM または同等の層。three.js のテクスチャに文字を焼きません。
- カメラの寄りと回転は、図の層に掛けます。文字が図に埋もれたり、画面の端で欠けたりしないようにします。
- 安全域の目安は、1920×1080 で左右 80px、上下 64px。意図した出入りは、対象と理由を検査結果に書きます。
- 字形を崩したり、1字ずつ常時揺らしたりして動きを稼ぎません。全文字幕、制作管理番号、章表示、テロップ帯、エンドクレジット、白フラッシュ、意味のない粒子は足しません。本編は明るい紙色です。ライムはエンドロゴの背景だけです。
- ロゴの動きは、0〜2.6秒で o が落ちてバウンドし定位置へ、2.6〜3.2秒で全体が左へ滑り、3.0〜4.0秒で「.work」が一文字ずつ出ます。そのあと完成形を 1〜1.5秒保持します。
- BGM と効果音は、この依頼の一気通貫には含めません。条件は `plan.html` の「音」にあります。音源が無いことを、映像の実装を止める理由にしません。音声が未制作なら、完成音声つきとは報告しません。

## 完成条件と検査

- 主張が、原稿を知らない視聴者に伝わる。0から100は崩れる、70から90は伸びる、最後の責任は人が持つ。
- 留保が、声か画面で読める・聞ける。元がなければ生成するしかない。短縮自体は悪くない。反応が厳しすぎることもある。少しAIくさくても注文をやめるとは限らない。手抜きと受け取られれば客は離れる。思い出は置き換えられない。
- 最後は本人の肯定で閉じる。視聴者への問いかけで中立にしない。個人の経験を、全員の成功の保証にしない。
- 文字の機械検査を通し、意図した出入りと実際の欠陥を分けて書く。検査の成功を、見た目の合格と同一視しない。
- 冒頭、中盤、後半、場面のあいだ、ロゴを、動画として確認する。再生していない範囲は未確認と書く。
- 企画書の絵と一致していることではなく、主張の明快さ、視覚的な魅力、可読性で評価する。

## 届け方

作業ブランチを切り、そこに実装と報告を置いてください。main へ直接コミットしません。プルリクエストを作り、マージしません。公開、投稿、購入はこの依頼に含めません。既存の権限と費用の承認の範囲を守ります。パスワードや API キーを、コード、資料、ログに残しません。

## 報告に含めること

- 何をどう変えたか。主張、字組み、画面全体の動き、場面のつなぎにどう表れたか。
- 文字検査の結果。間隔、安全域、欠陥の件数、直したあとに同じ検査を通したか。意図して残した出入り。
- 動画で確認した範囲と、未確認の範囲。実速で再生していない場合は、未確認と書く。
- 音声と BGM が未制作であること。その前提で尺を見ていること。
- 使ったモデルの名前と、Claude Code のバージョン。環境が返した値を書く。メモにある識別子を、実行せずに確定情報として書かない。
- `video/progress.md` の開始と完了。暦の日数の見積もりは使わない。
- 実行環境の障害があれば、試した方法、障害、完成した範囲。

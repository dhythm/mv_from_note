# 企画へのフィードバック（20261003）

「なぜSNSで見つけた便利ツールは続かないのか」の制作でつまずいた点と、次の企画で意識してほしいこと。

## 1. 表現の方針を、企画の最初に決める

企画書は「文字は最後の一文だけ、音楽なし、画で語る」前提で書かれていました。
しかし制作では「主張を文字で段階的に打ち出す」「BGMを付ける」に変わり、企画書のタイムラインや動きの設計がほぼ使えなくなりました。

- 文字の量（最後だけ／要所だけ／主張を全部）、ナレーションの有無、BGMの有無は、最初に決めて企画書に書く。
- 「音なし」は、見る側にはシンプルすぎると受け取られた。音を外すなら理由を書く。

## 2. 主張の筋は、記事全体から取る

references.md は記事の一部しか抜いておらず、制作側はそれだけで組んだ結果「何が言いたいのか分からない」映像になりました。
抜けていたのは次の部分です。

- 導入の問い（「これが便利！」を試しても、続いているものは驚くほど少ない。なぜか）
- 原因の核心（汎用的になるほど効力は薄まり、特化するほど高まる）
- 転換（参考にするのは悪くない。続いているのは「そのまま使っていない」もの）
- 方法（自分を観察する → 「なぜ便利なのか」を考えて自分に合わせる）
- 比喩（教わった便利は種。自分という土壌で育てる）

次回は、企画書に記事の骨組みを書いてください。「問い → 原因 → 転換 → 方法 → 結論」のように見出しごとの主張を1行ずつ並べ、映像のどこでそれぞれを伝えるかを対応させてください。

## 3. 企画の比喩が、記事の主張とずれないようにする

「1つだけ残る」「手は新しいものを足さない」は企画で作った比喩で、記事には書かれていません。
記事が言っているのは「数を絞る」ことではなく、「そのまま使わず、自分に合わせて育てる」ことです。
比喩を考えたら、それが記事のどの文に対応するかを書き添えてください。対応する文がなければ、その比喩は使わない。

## 4. 「画面に出す言葉」と「演出の指示」を分けて書く

「朝の机が空」「中身は見ずに、置く。」「山が自重で崩れる」は演出の指示（ト書き）でした。それを画面に出すと、見る人には意味が通りません。
企画書では次の2つを分けてください。

- 画面に出す言葉: 見る人が企画書なしで読んで意味が通るもの
- 演出の指示: 制作側だけが読むもの

また、冒頭で何の話かを言う一文を、必ず企画に入れてください。

## 5. 尺と文字量の見積もりを入れる

読める速さは1秒あたり約7文字＋1拍。90秒で読ませられる文字は約350文字が上限でした（今回の完成版で356文字）。
企画の段階で言葉の案を並べたら、合計の文字数を数えて尺に収まるか確かめてください。収まらない分は制作側が言い回しを縮めることになり、承認後に文言が変わる原因になります。

## 6. 素材の整合を、企画の段階で確かめる

静止画のずれを演出でごまかした箇所が複数ありました。

- **画角**: 01〜03 と 04〜06 で違う（47秒でカメラが動いたように見える）。全カットを同じ画角で作る
- **状態の連続**: 06 のノートが、05 で手が変えた角度から元に戻っている（「手を入れた」が画の上で取り消される）。前のカットの結果を次のカットに引き継ぐ
- **物の一致**: 03 の花瓶が 04 ではランプになっている
- **途中の状態**: スマホ1台から、完成した山へいきなり飛ぶ。積み上がる途中の画が1〜2枚あるとつながる
- **手の動き**: 企画書にある「手が置く」画がない
- **文字を置く余白**: 文字中心にするなら、壁などの空いた面を画の中に確保する（04 以降は壁の帯が細く、文字の置き場に苦労した）
- **解像度**: 1280x720 で作ってある。1080p で出す可能性があるなら 1920x1080 で用意する

## 7. 不要な要素は企画書に書いておく

制作側が足した右下の章表示（「02 ── 原因」）は不要と判断されました。章表示・テロップの帯・ロゴなど、入れてほしくない要素があれば企画書に書いてください。

## 8. 企画書のルールと、実際の運用をそろえる

企画書には「生成用のプロンプトはリポジトリに置かない」とありますが、今回は再現用に prompt.md を書き出しています。
このルールを残すか、prompt.md を git 管理外にするかを決めてください。

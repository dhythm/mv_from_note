# 動画制作プロンプト

note の記事1本から、キネティックタイポグラフィ中心のモーショングラフィック動画を作るためのプロンプト。
今回（20261003「なぜSNSで見つけた便利ツールは続かないのか」）のやり取りで決まったことを、最初から全部入れてある。
`{}` の部分を差し替えれば、ほかの記事にも使える。

---

## プロンプト本文

```
{企画ディレクトリ}（例: 20261003_なぜSNSで見つけた便利ツールは続かないのか/）にある
plan.md（企画書）・references.md（記事の引用）・assets/（静止画）をもとに、
キネティックタイポグラフィ中心のモーショングラフィック動画を作ってください。

# 目的
元記事 {記事URL} の主張を、見た人が「何が言いたいのか」分かる形で伝える。
ただ文字を順に出すだけの単調な映像にはしない。視覚的に面白い動きを入れつつ、要点ははっきり打ち出す。

# 進め方（この順で。各段階で止まって確認を取ること）
1. 元記事を必ず全文読む。references.md は抜粋なので、それだけで筋を組まない。
   note の本文は https://note.com/api/v3/notes/{記事ID} の data.body から取れる。
2. 記事の筋を「問い → 原因 → 転換 → 方法 → 結論」のような骨組みに分ける。
   記事の見出しと、各見出しの主張・具体例・結論を漏れなく拾う。
3. 画面に出す言葉の台本を script.md に書き、私の OK をもらってから実装する。
   台本は「秒｜言葉｜引用か要約か｜画と動き」の表にする。
4. 実装（Remotion）→ 静止画で確認 → 全編を書き出す → 報告。

# 画面に出す言葉のルール
- 冒頭で、何の話か（記事のタイトルの問い）を必ず言う。
- 画面の言葉は、企画書を読んでいない人が見ても意味が通ること。
  企画書の演出指示（ト書き）や、画の比喩だけで成り立つ言葉（例:「中身は見ずに、置く。」「1つだけ、残す。」）はそのまま出さない。
- 記事にない主張を足さない。企画書の比喩が記事の主張とずれていたら、記事を優先する。
- 記事の文そのまま（引用）は明朝体、要約・つなぎの言葉はゴシック体で書き分ける。
  引用は references.md の文と一字一句同じにする（足りない引用は references.md に追記し、記事本文と照合する）。
- 1つの言葉のまとまりは「7文字/秒 + 1拍」以上、止まって読める時間を取る。
  90秒で読ませられるのは約350文字が上限。収まらなければ言い回しを縮めて、縮めた箇所を報告する。
- 言葉のまとまり同士は重ねない。
- 章立て・パート名のラベル（右下の「02 ── 原因」のような表示）は出さない。

# 画と動き
- 1280x720、30fps、90秒。
- 机の写真はカメラ固定のまま動かさない（パン・ズームなし）。切り替えはクロスフェードだけ。動くのは文字と図形。
- 文字は写真の空いている所（壁など）に置く。写真の主役（スマホ・山・ノート・手）には重ねない。
  明るい壁には暗い文字、暗い所には白い文字＋影かグラデーションの下敷き。画ごとに空き場所が違うので、画ごとに配置を決める。
- 言葉の意味を動きで見せる。今回うまくいった例:
  - 「これが便利！」の投稿カードがスマホから飛び出し、机に積もり、ほとんどが消える（取り入れても続かない）
  - 「朝型／夜型」で画面が夜の色に沈む。札の文字が版ずれしていく（合わない）
  - 「汎用的なほど薄い」は字間が開いてぼやけ、「特化するほど高い」は締まってくっきりする
  - 「最適解」の引用が震えて1文字ずつ落ち、紙片が降って山が崩れる
  - 「順番を入れ替えてみます」は、語のカードを実際に入れ替えて文に組み上げる
  - 「育てるもの」でノートから机に根が張る
  - 「作り上げるものです」は1文字ずつ上から積み上がる
- 静止画どうしで画角や物の位置がずれる所（今回は 03→04 の画角、05→06 のノートの角度）は、
  崩落の紙片や根の線など、画面を覆う動きの最中に切り替えて目立たせない。
- 最後に記事タイトルを小さく出して元記事につなぐ。実在のサービス名やロゴ（note など）は出さない。

# 音
- BGM を付ける（無音にしない）。ナレーションは入れない。
- 権利の心配がないよう、BGM はこの映像のためにコードで合成する（外部音源を使わない）。
  素材サイトの曲を使う場合は、候補と利用規約を示して私の許可を取ってから。
- 画面の出来事に音を合わせる（カードが飛ぶ粒、崩れる前の上昇と一撃、語の入れ替え、最後の一文の積み上げ、最後のフェードアウト）。
- 音量は -14〜-16 LUFS 程度を目安にし、測った値を報告する。耳で確認できない場合はそう明記する。

# 実装の決まり
- Remotion（TypeScript、class ではなく function）。プロジェクトは {企画ディレクトリ}/video/ に置き、
  remotion.config.ts で publicDir を ../assets にして静止画をコピーしない。
- 言葉と秒数は src/lib.ts の1か所（BEATS）にまとめる。各シーンはそこを参照する。
- TDD で進める。最低限、次をテストする:
  - 尺が 90秒・30fps でパートに隙間がない
  - 各言葉のまとまりの静止時間が「7文字/秒 + 1拍」以上
  - 言葉のまとまりが重ならず、90秒に収まる
  - 引用部分が references.md の文のまま
  - 乱数は種付き（毎回同じ画になる）、配置計算や合成器などの純粋関数
- 書き出す前に、各パート2枚ほど静止画を書き出して自分の目で確認する（文字の読みやすさ、主役との重なり、切り替えのごまかし）。
- 全編を output/{日付}.mp4 に書き出し、ffprobe で 90秒・1280x720・30fps・音声ありを確認する。
  output/ と *.mp4 は git 管理外。コミットは私が指示するまでしない。

# 報告に含めること
- 動画のパスと仕様（ffprobe の結果）
- パートごとの流れ（1行ずつ）
- 企画書や承認済みの台本から変えた点（言い回しの短縮も含む）
- 静止画の都合でごまかしている所と、追加で集めた方がいい素材
- BGM を自分で聴けていない場合はそのこと
```

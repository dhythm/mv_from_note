# 企画書（plan.html）の書き方へのフィードバック

2026-11-02。企画のコミット `9db0c79` の plan.html に対するユーザーのレビュー。企画の中身（主張・カット・文言）への指摘ではなく、企画書という文書の構成と見た目への指摘。次回以降の企画書に適用する。共通方針は `AGENTS.md` の「企画書兼作業指示書に書くこと」に反映した。

## 1. 結論ファーストで書く。絵コンテを詳細より先に置く

コミット時点の plan.html は、伝える一文と視聴者のあとに「声・文字・素材の分担」「企画側／制作側」「デザインシステム」「動きの言語」「記号と色」「キャラ設定」の6節が続き、構成と尺・絵コンテはその後ろにあった。ユーザーの指摘は「うだうだと最初に書いて、最後の方に絵コンテを入れるのは微妙」。

企画書は読む人のためにある。読み手が最初に知りたいのは「どんな動画にするか」「どういう構成か」「絵コンテはこんな感じ」で、分担やデザインシステムの細則はそのあとに「詳細は以下」として読めればよい。画を見る前に記号や動きの名前の定義を読まされると、何のための決まりかがつかめない。

次回からの順番：

1. 前半：基本情報 → この動画で伝える一文 → 視聴者 → 構成と尺 → カット表・絵コンテ → 未確定事項・判断してほしい点
2. 「詳細（ここから下は補足）」の区切り
3. 後半：声・文字・素材の分担、主張・根拠・留保の対応、企画側／制作側、デザインシステム、動きの言語、記号と色、キャラ設定、差し替え候補、素材、音、根拠、完成条件・確認状態

主張・根拠・留保の対応表は、どのカットが根拠を担うかの表なので、絵コンテを見たあとの後半に置く。冒頭は一文だけにして軽く読ませる。カットの中で使う後半の用語（E_SLAM などのイージング名）は、最初に出る箇所から定義へリンクする。

この企画の plan.html は、文言を変えずに節の順番だけをこの形へ並べ替えた。

## 2. 判断が要る点を、情報と分けて集め、色で強調する

ユーザーの指摘：役割分担、企画側／制作側、動きの言語化などは基本的に「情報」で、読めば済む。一方、差し替え候補や未確定事項は判断が要る。企画書のどこが「こういう情報です」で、どこが「この辺どうしますか」なのかが分かれていないと、どこをチェックすればよいか分からない。判断が要る点はまとめ、色を付けて強調してほしい。

この企画の plan.html では次のようにした（文言は変えていない）。

- 「未確定事項と判断してほしい点」を冒頭の基本情報の直下へ移し、注意色（orange）のパネルにした。5 項目に番号を付け、各項目から本文の該当箇所へリンクした。
- 本文の該当箇所（仮題、声・文字・素材の分担の注記、差し替え候補の節とカット04・10 の枠、カット07、音の節）に同じ番号の「要判断 n」の印を付けた。
- 目次の先頭に「判断してほしい点（5）」を同じ色で置いた。
- 要判断の色は、決定済みの情報（無彩色・青）には使わない。

§1 の並べ替えの時点では「判断してほしい点」を絵コンテの直後に置いたが、判断する項目を先に知っていれば、読みながら該当箇所を意識できる。各項目から該当箇所へ飛べるので、絵コンテを見る前でも判断の文脈は失われない。

## 3. 企画書の見た目はデジタル庁デザインシステム（DADS）で統一する

plan.html の見た目を DADS のトークン（`@digital-go-jp/design-tokens`）に合わせて作り直したところ、ユーザーは「結構見やすい」「統一感ができるなら今後すごく見やすくなる」と評価した。

次回からは、この企画の plan.html の `<style>` を複製して使う。白背景、灰色の文字、青の基調色、Noto Sans JP 16px・行間1.7、8pxの倍数の余白、下線つきのリンクと黒・黄のフォーカス。企画ごとに配色や装飾を作り直さない。引き渡し一式が別フォルダに依存しないよう、スタイルは各 plan.html の中に置く。DADS は企画書の見た目の規定で、動画本編の配色・字組みとは別。
